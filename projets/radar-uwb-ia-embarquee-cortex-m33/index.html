Radar UWB : classification par CNN en temps réel sur Cortex-M33

Vitesco Technologies / Schaeffler France · Alternance · M2 · Sept. 2024 – Oct. 2025

Pipeline embarqué complet pour un système automobile d’ouverture mains libres (Hands-Free Access) : acquisition radar UWB, traitement temps-fréquence par FFT sur DSP, inférence CNN temps réel sur ARM Cortex-M33 (128 kB RAM, 768 kB Flash).

01Contexte

Le modèle précédent (CNN 1D temporel) devait être ré-entraîné pour chaque véhicule. L’objectif était de concevoir une approche universelle basée sur une représentation temps-fréquence, déployable en temps réel sur le MCU Ranger5 NXP sans compromis sur les performances.

02Chaîne technique

  1. 1Acquisition CIR UWB
  2. 2FFT 32 pts + Hanning
  3. 3Images temps-fréquence 20×23×6
  4. 4CNN Conv2D compact
  5. 5Inférence INT8 temps réel

03Ce que j’ai réalisé

  1. 01

    Simulation MATLAB du DSP embarqué via NXP DSP Toolbox pour répliquer le comportement du Ranger5 et générer ~1100 images temps-fréquence (CSV) depuis des enregistrements CIR multi-véhicules. Mise à jour de l’algorithme de trigger (segmentation IQ, fenêtre 384 points).

  2. 02

    Prétraitement Python : normalisation par tap, clipping CIR (6×32 → 6×20), augmentation par modulation fréquence, suppression gestes faux par similarité cosinus inter-taps, adaptation données legacy (SNR 6,7→11,2) par alignement statistique tap par tap.

  3. 03

    Conception CNN Conv2D avec optimisation automatique Optuna (400 trials, objectif multi-critères : loss, TPR, 1-FPR, taille, latence). Contraintes dures : <25k paramètres, <80 kB float, <30 kB après quantification. AdamW + ReduceLROnPlateau.

  4. 04

    Optimisation modèle : pruning graduel (~49 % sparsité/couche), weight clustering (ratio 95,62 %), QAT 2 phases + PTQ INT8 — réduction taille de 50,94 % (24,33→11,94 kB).

  5. 05

    Implémentation C embarquée du pipeline FFT (autocoder MATLAB insuffisant) : BbCopy, Hanning, FFT 32 pts, ComplexToPolar, accumulation buffer. Intégration TFLite Micro : resolver opérateurs, tensor arena statique (~60 kB/128 kB RAM), quantification int8 entrée.

  6. 06

    Tests terrain (clinic) : 3 participants, catalogue de kicks, lecture CAN via Arduino + buzzer. Pipeline end-to-end validé sur Ranger5 : 70 % détection, 100 % immunité faux positifs.

05Difficultés rencontrées

  • Réimplémentation manuelle complète du pipeline FFT en C (MATLAB autocoder incomplet sur fonctions DSP custom)
  • RAM 128 kB : tensor arena 60 kB, ajustement itératif par essais/erreurs pour éviter les OOM
  • Pruning/clustering sans gain réel sur TFLM Cortex-M33 (absence de sparse kernels natifs)
  • Adaptation données legacy (différences SNR hardware) par alignement statistique tap par tap et véhicule
  • Mismatch Python/C embarqué : preprocessing pas encore parfaitement aligné, baisse de détection en conditions réelles
