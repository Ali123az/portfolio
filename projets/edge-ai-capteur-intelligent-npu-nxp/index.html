Edge AI : capteur intelligent sur microcontrôleur à NPU intégré

Pipeline Edge AI complet : acquisition accéléromètre via SPI, génération dataset, entraînement CNN Conv1D, quantification INT8, déploiement sur NPU Neutron NXP — accélération ×42 sur opérations Conv1D int8.

01Contexte

Projet réalisé dans le cadre de mon stage chez NXP Semiconductors, en lien avec l’ENSEEIHT. Objectif : démontrer une chaîne Edge AI complète sur un microcontrôleur à NPU intégré (carte FRDM-MCXN947), suffisamment documentée pour servir ensuite de support de travaux pratiques.

02Chaîne technique

  1. 1FXLS8974 via SPI
  2. 2Machine à états C
  3. 3Dataset CSV (UART)
  4. 4CNN Conv1D GPU
  5. 5PTQ INT8
  6. 6NPU Neutron eIQ

03Ce que j’ai réalisé

  1. 01

    Configuration hardware sur MCXN947 : SPI master (LPSPI non-bloquant), GPIO, timer, UART via SDK NXP.

  2. 02

    Machine à états C (INIT→ACQUIRE→SAVE→SEND) synchronisée sur INT1 de l’accéléromètre FXLS8974. Lecture complément à 2 via SPI non-bloquant, conversion décimal. Script Python UART→CSV avec parsing regex.

  3. 03

    Collecte manuelle du dataset : gestes (chiffres 0–9), organisation par classe pour entraînement supervisé.

  4. 04

    Conception et entraînement CNN Conv1D (3 couches conv, BatchNorm, Dropout, AveragePooling, Dense — 13 010 paramètres). Entraînement GPU avec EarlyStopping + ReduceLROnPlateau. Accuracy 99,3 %.

  5. 05

    Quantification PTQ int8 avec representative dataset, conversion float32→int8, évaluation post-quantification. Estimation mémoire via tflite-tools (peak : 131 440 bytes).

  6. 06

    Déploiement NPU : conversion via eIQ Portal (Neutron Converter), suppression couche Softmax non supportée (tflite-extractor). Intégration C++ MCU : import .tflite en .rodata, MicroMutableOpResolver, ajustement scale/zero-point.

  7. 07

    Rédaction du guide technique de déploiement (37 pages), réutilisé comme document de référence.

05Difficultés rencontrées

  • Compatibilité toolchain : GNU ARM Toolchain v12.3 requise (v13.2 incompatible avec le NPU)
  • NPU supporte uniquement int8 PCQ : suppression obligatoire de la couche Softmax via tflite-extractor
  • Peak RAM difficile à prédire empiriquement (131 kB estimé → 256 kB alloués avec marge de sécurité)
  • Débogage MCU : erreurs JSON probe, conflits port série, synchronisation sur INT1 accéléromètre
